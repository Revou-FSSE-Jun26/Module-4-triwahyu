# Repository Structure Rules

- API code lives in `backend/app/blueprints/<feature>/`. Each blueprint has `routes.py`, `service.py`, `schema.py` and an `__init__.py` that creates the `Blueprint` and imports its routes.
- Shared persistence models are in `backend/app/models/` (one file per entity); migrations are in `backend/migrations/`; shared helpers (errors, responses, validation, auth) are in `backend/app/common/`.
- Next.js routes are in `frontend/src/app/`; shared UI in `frontend/src/components/shared/`; hooks in `frontend/src/hooks/`; API and utility code in `frontend/src/lib/`.
- **Specs.** Author each slice in `.kiro/specs/NN-name/{requirements,design,tasks,CHANGELOG}.md`. The root `specs/` folder is **generated** from those files by `python scripts/build_specs.py` and drift-checked in CI. Never edit `specs/` by hand.
- **Guidelines.** `guidelines/{backend,database,frontend}.md` are canonical. `.kiro/steering/*` include them; do not copy rules into steering.
- **Contracts.** Behaviour shared across features lives once in `docs/contracts/` (error envelope, permissions, ordering, deletion).
- `contracts/openapi.json` is generated by `python scripts/export_openapi.py`; do not hand-edit it.
- Keep root `AGENTS.md` short and point agents to steering.
- Avoid duplicate sources of truth for API contracts, permissions, ordering, and error envelopes.
- Test reports for deployment evidence are committed under `frontend/e2e-report/<target>/`; `playwright-report/` and `test-results/` stay ignored.
